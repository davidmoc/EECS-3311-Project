### **UC01 — Browse Current News**

**Actors:** User, News Provider, LLM Service

**Goal:**  
Allow the user to quickly understand major current political and world events from the homepage without needing to initiate a chat or research session.

**Preconditions:**  
The application is running and can access at least one configured news source.

**Trigger:**  
The user opens the homepage or refreshes the news dashboard.

**Main Success Scenario:**

1. The system requests recent news from the configured News Provider.
2. Retrieved articles are grouped around underlying events.
3. Duplicate or substantially overlapping reports are consolidated.
4. The LLM Service generates concise event summaries from the retrieved reporting.
5. The system presents event cards containing the event title, brief summary, date, and relevant categories.
6. The user browses the dashboard and may select an event for further exploration.

**Alternative/Exception Flows:**

- If one news source is unavailable, the system continues using available sources.
- If an event cannot be summarized reliably, the system can present the retrieved headlines and sources without generating a definitive summary.
- If no current news can be retrieved, the system displays an error or previously cached information where available.

**Postconditions:**  
The user has been presented with an organized overview of current events. Selected events may be passed to UC02 or UC03.

**Related Feature(s):**  
F01 — News Dashboard

### **UC02 — Explore a News Event**

**Actors:** User, News Provider, LLM Service

**Goal:**  
Allow the user to move from a brief news-dashboard entry to a more detailed understanding of a specific event.

**Preconditions:**  
A news event has been identified by the system and is available from the dashboard or another part of the application.

**Trigger:**  
The user selects a news event.

**Main Success Scenario:**

1. The system retrieves the event and its associated articles.
2. Additional reporting is retrieved if the current information is insufficient.
3. The system presents an expanded event summary.
4. Relevant articles, dates, and sources are displayed.
5. The system presents important contextual information where available.
6. The user may inspect the source material directly.
7. The user may choose to begin a full research session using the event as the research subject.

**Alternative/Exception Flows:**

- If additional reporting cannot be retrieved, the system displays the information already available.
- If sources disagree about important factual details, the disagreement is shown rather than silently resolved.
- If the event is still developing, the system indicates that available information may change.

**Postconditions:**  
The user has a more detailed view of the event and may initiate UC03 — Conduct Political Research.

**Related Feature(s):**  
F02 — Expandable Event Exploration  
F03 — Multi-Step Political Research Agent

### **UC03 — Conduct Political Research**

**Actors:** User, LLM Service, News Provider, Web Search Provider, Document Provider

**Goal:**  
Investigate a political, historical, or current-events question through an iterative research process centered on historical and dialectical materialism.

**Preconditions:**  
The application has access to the research agent and at least one usable information-retrieval source.

**Trigger:**  
The user submits a research question or selects “Research this event” from another part of the application.

**Main Success Scenario:**

1. The user submits a research objective.
2. The system creates a `ResearchSession`.
3. The Reader Model is consulted for relevant prior knowledge and interests.
4. `ResearchPlanner` creates an initial research plan.
5. The agent retrieves initial evidence using the available tools.
6. `ConcreteSituationBuilder` constructs an initial representation of the situation.
7. The dialectical-materialist research method evaluates the developing situation, including its material conditions, historical development, social relations, institutions, contradictions, and unresolved questions.
8. The agent identifies missing relationships, relevant historical questions, conflicting evidence, or poorly supported interpretations.
9. `ResearchPlanner` revises the research plan and schedules additional research commands.
10. The agent retrieves further evidence and updates the `ConcreteSituation`.
11. Steps 7–10 repeat until the `ResearchStoppingPolicy` determines that the research is sufficiently developed or the configured research budget has been reached.
12. The system synthesizes a `MaterialistAnalysis`.
13. The final `ResearchResult` is presented with supporting evidence, citations, unresolved questions, and suggested readings.

**Alternative/Exception Flows:**

- If the research question is ambiguous, the system requests clarification or presents possible interpretations.
- If a retrieval tool fails, the agent retries where appropriate or uses an alternative source.
- If conflicting evidence is discovered, it is recorded and investigated rather than discarded.
- If insufficient evidence exists for a claim, the claim is marked as uncertain or excluded from the final analysis.
- If the research budget is reached before all questions are resolved, the system returns the best-supported result available and identifies remaining gaps.
- If no meaningful evidence can be found, the system informs the user rather than fabricating an analysis.

**Postconditions:**  
A persistent research session and source-grounded research result are available. The user may save the result, inspect its evidence, continue the research, or follow recommended readings.

**Related Feature(s):**  
F03 — Multi-Step Political Research Agent

F10 — Source and Framing Comparison  
F11 — Marxist Theoretical Analysis  
F14 — Personalized and Adaptive Assistance  
F15 — Personal Research and Reading Workspace

### **UC04 — Ask a Source-Grounded Question**

**Actors:** User, LLM Service, Web Search Provider, Document Provider

**Goal:**  
Answer a natural-language question while emphasizing relevant source material rather than replacing the sources with an unsupported AI-generated response.

**Preconditions:**  
The conversational interface is available and the system can access relevant stored or external sources.

**Trigger:**  
The user submits a question.

**Main Success Scenario:**

1. The system interprets the user’s question.
2. Relevant reader-profile information and conversation context are retrieved.
3. The agent determines what supporting material is required.
4. Relevant documents and passages are retrieved.
5. The system selects source passages directly relevant to the question.
6. The LLM produces an explanation grounded in the retrieved material.
7. The response displays appropriate source passages, citations, annotations, and explanatory text.
8. Relevant additional readings may be recommended.

**Alternative/Exception Flows:**

- If no adequate source is found, the system indicates that the answer cannot be sufficiently grounded.
- If the question is ambiguous, clarification may be requested.
- If licensing restrictions prevent substantial reproduction of a text, the system provides permitted excerpts and links to the original source.
- If sources conflict, the disagreement is presented to the user.

**Postconditions:**  
The user receives a source-grounded response and can continue the conversation, open the underlying texts, or begin a deeper research session.

**Related Feature(s):**  
F04 — Source-First Question Answering  
F14 — Personalized and Adaptive Assistance

### **UC05 — Browse/Search the Reading Library**

**Actors:** User, Document Provider

**Goal:**  
Allow the user to independently discover and access books, essays, articles, and other relevant political or historical texts.

**Preconditions:**  
The library catalogue is available.

**Trigger:**  
The user opens the library, enters a search query, selects a category, or applies a filter.

**Main Success Scenario:**

1. The user enters a search term or browses available categories.
2. `LibraryService` searches internal metadata and configured document providers.
3. The system returns relevant documents.
4. Results display title, author, date, topic, description, source, and availability information.
5. The user selects a text.
6. The system opens the text in the reader or provides a legal download option where available.

**Alternative/Exception Flows:**

- If no exact matches are found, related texts may be suggested.
- If a document is no longer available externally, the system informs the user.
- If direct download or reproduction is not permitted, the system links to the source rather than redistributing the document.

**Postconditions:**  
The user has located relevant source material and may begin reading it.

**Related Feature(s):**  
F05 — Reading Library and Text Search

### **UC06 — Read and Annotate a Text**

**Actors:** User, LLM Service, Document Provider

**Goal:**  
Allow the user to read source material directly while optionally receiving contextual AI annotations.

**Preconditions:**  
A document is available in the reader.

**Trigger:**  
The user opens a document or requests an annotation for a passage.

**Main Success Scenario:**

1. The selected document is displayed in the reader.
2. The system records reading progress.
3. The user reads the original text.
4. Existing annotations are displayed where appropriate.
5. The user requests an annotation for a passage or opens an existing one.
6. The system retrieves any additional context needed for that annotation.
7. The LLM generates the requested annotation.
8. The annotation is displayed separately from the author’s original text.
9. The user can follow links to relevant context or recommended material.

**Alternative/Exception Flows:**

- If additional information needed for an annotation cannot be verified, the annotation indicates uncertainty.
- If the text is unavailable, the system informs the user.
- If the selected passage is too ambiguous without surrounding context, the system incorporates additional surrounding text before generating the annotation.

**Postconditions:**  
The user’s reading progress is updated and any generated annotation is associated with the appropriate passage.

**Related Feature(s):**  
F06 — AI-Annotated Reading

### **UC07 — Get Reading Recommendations**

**Actors:** User, LLM Service, Document Provider

**Goal:**  
Recommend source material appropriate to the user’s current interests, research objective, knowledge, and reading history.

**Preconditions:**  
The library contains or can retrieve relevant material.

**Trigger:**  
The user requests reading recommendations or encounters a recommendation generated by another feature.

**Main Success Scenario:**

1. The system identifies the topic or learning objective.
2. The Reader Model is consulted.
3. The system searches for suitable texts.
4. Previously completed or clearly redundant readings are deprioritized.
5. The LLM evaluates the relevance and difficulty of available material.
6. The system presents recommended texts with an explanation of why each is useful.
7. The user can open, save, or download a recommended text.

**Alternative/Exception Flows:**

- If little is known about the user, recommendations are based primarily on the requested topic.
- If no suitable text is available in the internal library, external source recommendations may be shown.
- If the user’s profile is inaccurate, the user can correct it through UC13.

**Postconditions:**  
The user receives a set of relevant readings and may begin one of them.

**Related Feature(s):**  
F07 — Intelligent Reading Recommendations

### **UC08 — Follow a Prerequisite Learning Path**

**Actors:** User, LLM Service, Document Provider

**Goal:**  
Help the user acquire background knowledge necessary to understand a more advanced topic or text.

**Preconditions:**  
The system has identified a target topic or document.

**Trigger:**  
The user requests a learning path or the system detects potentially important prerequisite gaps.

**Main Success Scenario:**

1. The system identifies concepts and historical knowledge assumed by the target material.
2. The Reader Model is consulted to determine which prerequisites the user already understands.
3. Known prerequisites are filtered out.
4. The system searches for relevant introductory material.
5. The agent creates an ordered learning path.
6. Each step includes an explanation of why it is relevant and one or more suggested readings.
7. The user progresses through the path and marks or demonstrates completion.
8. The Reader Model is updated as appropriate.

**Alternative/Exception Flows:**

- The user can skip a prerequisite or indicate that they already understand it.
- If the system lacks confidence in a knowledge assessment, it presents the prerequisite as a suggestion rather than a requirement.
- If no appropriate reading exists, the system may provide a basic orientation and identify the gap.

**Postconditions:**  
The user has a personalized sequence of prerequisite material and progress can be retained.

**Related Feature(s):**  
F08 — Prerequisite-Guided Learning  
F13 — Adaptive Reader Model  
F14 — Personalized and Adaptive Assistance

### **UC09 — Explore Historical Context**

**Actors:** User, LLM Service, Web Search Provider, Document Provider

**Goal:**  
Help the user understand how a present or historical situation developed over time.

**Preconditions:**  
A topic, event, source, or research question has been identified.

**Trigger:**  
The user explicitly requests historical context or opens a context link from another feature.

**Main Success Scenario:**

1. The system identifies which historical developments are relevant to the selected topic.
2. Historical source material is retrieved.
3. The system identifies important origins, stages, continuities, turning points, and structural changes.
4. Evidence supporting those developments is retained.
5. The LLM organizes the material into a coherent historical explanation.
6. Relevant texts and passages are presented for deeper reading.

**Alternative/Exception Flows:**

- If historical interpretations differ, the system distinguishes factual chronology from contested interpretation.
- If evidence is incomplete, gaps are identified.
- If the user’s request covers an excessively broad period, the system may ask the user to narrow the scope.

**Postconditions:**  
The user receives a source-grounded account of the relevant historical development.

**Related Feature(s):**  
F09 — Historical Context Exploration

### **UC10 — Compare Sources and Framing**

**Actors:** User, LLM Service, News Provider, Web Search Provider

**Goal:**  
Allow the user to compare how different sources describe and frame the same event or issue.

**Preconditions:**  
At least two sufficiently related sources are available.

**Trigger:**  
The user requests a comparison or selects multiple sources.

**Main Success Scenario:**

1. The selected documents are retrieved.
2. The system identifies overlapping factual claims and comparable passages.
3. Source-profile information is retrieved where available.
4. The LLM identifies differences in terminology, emphasis, framing, omitted context, and evidence used.
5. Material information about source ownership, institutional affiliation, or funding is included where relevant and verifiable.
6. The comparison is displayed alongside the underlying passages and sources.

**Alternative/Exception Flows:**

- If the selected sources are not sufficiently comparable, the system warns the user.
- If source-profile information is unavailable, no unsupported inference is made.
- If the sources disagree about facts, the disagreement is distinguished from differences in framing.

**Postconditions:**  
The user receives a structured source comparison and can inspect the underlying material directly.

**Related Feature(s):**  
F10 — Source and Framing Comparison

### **UC11 — Request Marxist-Theoretical Analysis**

**Actors:** User, LLM Service, Document Provider

**Goal:**  
Help the user examine a topic using Marxist-Leninist principles centered on historical and dialectical materialism while grounding the analysis in source material.

**Preconditions:**  
A topic, event, research corpus, or question is available.

**Trigger:**  
The user explicitly requests theoretical analysis or such analysis is reached as part of a broader research session.

**Main Success Scenario:**

1. The relevant factual and historical material is gathered or reused from the current research session.
2. The system identifies material conditions, class and production relations, institutions, historical development, contradictions, ideological factors, and other relevant relationships.
3. Relevant Marxist theoretical texts are retrieved.
4. The agent connects the theoretical material to the evidence.
5. Interpretive claims retain links to supporting evidence.
6. The system presents the analysis together with citations, relevant passages, and suggested theoretical readings.

**Alternative/Exception Flows:**

- If the available evidence does not justify a strong theoretical conclusion, the system presents a tentative interpretation.
- If multiple plausible interpretations exist within Marxist analysis, the disagreement may be noted.
- The system does not force every issue into a predetermined category when the evidence does not support doing so.

**Postconditions:**  
The user receives a source-grounded Marxist-Leninist analysis and can inspect or continue studying the theory used.

**Related Feature(s):**  
F11 — Marxist Theoretical Analysis

### **UC12 — Explore Related Leftist Traditions**

**Actors:** User, LLM Service, Document Provider

**Goal:**  
Introduce the user to other communist, socialist, anarchist, or related tendencies when understanding them would materially improve the user’s understanding of the topic.

**Preconditions:**  
The user is studying a topic for which another political tendency or theoretical disagreement is relevant.

**Trigger:**  
The user requests another perspective or the system identifies a relevant ideological or historical connection.

**Main Success Scenario:**

1. The system determines which political tendency is relevant.
2. Historical material concerning that tendency’s development is retrieved.
3. The system identifies the material and historical conditions surrounding its development.
4. Its major disagreement or relationship with the current topic is explained.
5. Representative texts are retrieved.
6. The user is encouraged to inspect the relevant source material directly.

**Alternative/Exception Flows:**

- If another tradition is not meaningfully relevant, the system does not introduce one merely to create artificial balance.
- If representative source material cannot be found, the system identifies the limitation.
- The system distinguishes the tradition’s own stated position from the application’s Marxist-Leninist analysis of it.

**Postconditions:**  
The user understands why the related tradition is relevant and has access to material for independent study.

**Related Feature(s):**  
F12 — Ideological Context and Related Traditions

### **UC13 — Review or Correct the Reader Model**

**Actors:** User

**Goal:**  
Allow the user to inspect and correct the information the system uses for personalization.

**Preconditions:**  
A Reader Profile exists.

**Trigger:**  
The user opens the profile or learning-model interface.

**Main Success Scenario:**

1. The system displays the user’s reading history, interests, knowledge areas, familiarity estimates, and other relevant profile information.
2. The user reviews the information.
3. The user modifies incorrect interests, knowledge assessments, or preferences.
4. The system validates the changes.
5. `ReaderProfileService` saves the updated profile.
6. Future personalization uses the corrected information.

- The user may remove an inferred item rather than replacing it.

- If profile persistence fails, the previous profile remains unchanged and the user is informed.

**Postconditions:**  
The Reader Model reflects the user’s corrections.

### **UC14 — Receive Personalized Assistance**

**Actors:** User, LLM Service

**Goal:**  
Adapt explanations, recommendations, prerequisites, and research assistance to the individual reader.

**Preconditions:**  
A user request or other feature requires assistance. A Reader Profile may exist, although personalization can fall back to general behavior when little information is available.

**Trigger:**  
Another use case requests personalized output.

**Main Success Scenario:**

1. The system retrieves the relevant portion of the Reader Model.
2. It determines the user’s likely familiarity with the current topic.
3. Known material is not unnecessarily re-explained.
4. Identified knowledge gaps are considered.
5. The LLM receives the relevant personalization context.
6. The generated response is adapted in terminology, depth, examples, prerequisites, and reading suggestions.
7. The response is presented through the originating feature.

**Alternative/Exception Flows:**

- If little is known about the user, the system provides a general response.
- If Reader Model information has low confidence, it is not treated as certain.
- The user can override the level of detail or correct the profile.

**Postconditions:**  
The originating interaction has been personalized without changing its underlying factual evidence.

**Related Feature(s):**  
F13 — Adaptive Reader Model  
F14 — Personalized and Adaptive Assistance

### **UC15 — Save and Resume Research or Reading**

**Actors:** User

**Goal:**  
Allow the user to preserve research and reading activity so that study can continue across sessions.

**Preconditions:**  
The user has an item that can be saved, such as a document, passage, research result, event, or annotation.

**Trigger:**  
The user selects a save action or reopens previously saved work.

**Main Success Scenario:**

1. The user selects an item to save.
2. The system creates a saved-item record containing a reference to the original material and relevant metadata.
3. The item is stored in the user’s workspace.
4. The user later opens the workspace.
5. Saved items are displayed.
6. The user selects an item.
7. The system restores the relevant reading, research, or event context.
8. The user continues from where they previously stopped.

**Alternative/Exception Flows:**

- If an external source is no longer available, retained metadata and legally stored material are displayed where possible.
- If saving fails, the original item remains unchanged and the user is informed.
- If a research session was incomplete, it can be restored as an incomplete session rather than marked complete.

**Postconditions:**  
The user’s material is preserved or restored for continued study.

**Related Feature(s):**  
F15 — Personal Research and Reading Workspace
