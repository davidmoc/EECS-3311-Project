
The proposed system contains the following 15 major features. Together, these features are designed around the principle that the AI agent should facilitate independent study and analysis rather than replace them. The system therefore emphasizes direct engagement with source material, guided research, comparison of perspectives, and personalized learning.

### **F01 — News Dashboard**

**Description:**  
The News Dashboard provides an at-a-glance overview of significant current political and world events. Rather than requiring the user to initiate every interaction with a prompt, the homepage presents a regularly updated collection of important events. Reports concerning the same underlying event can be grouped together rather than presented as an endless feed of individual articles.

**User Interaction:**  
The user opens the homepage and browses event cards containing headlines, short summaries, dates, and relevant categories. The user can select an event to expand it or begin researching it.

**Input:**  
Current news retrieved from configured external news and information sources.

**Output:**  
A concise, organized dashboard of significant current events.

**AI Involvement:** Hybrid.

**Expected Workflow:**  
The system retrieves recent news, identifies reports concerning the same events, organizes related reports, and uses the AI model to produce concise event summaries. The resulting event cards are displayed on the homepage.

**Error/Alternative Cases:**  
If a news source is unavailable, the system continues using available sources and indicates when information is limited. Events with insufficient information or uncertain grouping should not be presented as confidently established.

---

### **F02 — Expandable Event Exploration**

**Description:**  
A user can expand any event from the News Dashboard to move beyond the at-a-glance summary. The expanded view provides additional details, relevant reporting, important context, and related topics without requiring the user to begin a chat.

**User Interaction:**  
The user selects an event card from the News Dashboard and opens its detailed event view. From there, the user can inspect sources, explore related information, or choose to research the event further.

**Input:**  
The selected event and associated retrieved source material.

**Output:**  
A detailed event view containing an expanded explanation, relevant sources, context, and links to further research.

**AI Involvement:** Hybrid.

**Expected Workflow:**  
The application retrieves the stored information associated with the event, gathers additional information when necessary, and organizes it into a more detailed view. The user can subsequently send the event directly to the research workspace.

**Error/Alternative Cases:**  
If additional information cannot be retrieved, the system displays the information already available and informs the user that the event view may be incomplete.

---

### **F03 — Multi-Step Political Research Agent**

**Description:**  
The research agent allows a user to investigate a current event, historical event, political question, or other complex topic. Instead of immediately generating an answer, the agent determines what information is necessary, retrieves relevant material, investigates appropriate context and theory, and organizes the results for the user.

**User Interaction:**  
The user can enter a research question through the research interface or select **Research this event** from an existing news event. The user can inspect the resulting research and continue exploring individual parts of it.

**Input:**  
A natural-language research question, selected news event, or political topic, together with relevant user preferences and existing research context.

**Output:**  
A structured research result containing relevant factual information, sources, historical context, theoretical connections, and areas for further investigation.

**AI Involvement:** AI-based/Hybrid.

**Expected Workflow:**  
The agent interprets the research objective, creates a research plan, selects appropriate retrieval tools, gathers information, evaluates the retrieved material, identifies missing context, performs additional retrieval where necessary, and organizes the results into a source-grounded research view.

**Error/Alternative Cases:**  
If the request is ambiguous, the agent can request clarification or present possible interpretations. If a retrieval tool fails, the agent may retry, use another available source, or clearly identify the information it could not obtain. The agent should not fabricate missing evidence.

---

### **F04 — Source-First Question Answering**

**Description:**  
Users can ask natural-language questions about politics, history, current events, or Marxist theory. Rather than treating AI-generated prose as the primary source of knowledge, the system emphasizes relevant source material whenever possible. Appropriate passages are presented directly to the user alongside the agent’s explanations and annotations.

**User Interaction:**  
The user submits a question through the conversational interface. The response can contain source passages, citations, annotations, explanations, and links to further reading.

**Input:**  
The user’s question, relevant conversation/research context, reader profile, and retrieved source material.

**Output:**  
A source-grounded response containing relevant passages or references, explanations, annotations, and suggested further reading.

**AI Involvement:** Hybrid.

**Expected Workflow:**  
The agent interprets the question, determines what sources are needed, retrieves relevant material, selects useful passages, and presents them with sufficient context. The LLM explains relationships between the material or answers aspects of the question that require synthesis.

**Error/Alternative Cases:**  
If suitable sources cannot be found, the system states this rather than presenting an unsupported response as established fact. Where copyright or licensing restrictions prevent substantial reproduction of a source, the system provides permitted excerpts and directs the user to the original material.

---

### **F05 — Reading Library and Text Search**

**Description:**  
The system contains a browsable and searchable library of freely accessible political theory, history, articles, books, essays, and other relevant material. This allows the user to study texts directly instead of interacting exclusively through AI-generated responses.

**User Interaction:**  
The user browses categories, searches for texts or authors, filters the library, opens a text in the reader, or downloads an available copy.

**Input:**  
Search terms, categories, authors, topics, theoretical traditions, or other filters.

**Output:**  
Matching texts with relevant metadata, descriptions, categories, source information, and reading/download options.

**AI Involvement:** Hybrid.

**Expected Workflow:**  
The system searches its text catalogue and returns relevant material. Semantic or conceptual searches may use AI to identify texts that are relevant even when the user’s terminology does not exactly match the text metadata.

**Error/Alternative Cases:**  
If no suitable text is available, the system informs the user and may recommend related searches. A work should only be offered for direct download or substantial in-application reproduction when its source and licensing/public-domain status permit it.

---

### **F06 — AI-Annotated Reading**

**Description:**  
When reading a text in the application, users can access AI-generated annotations associated with particular passages. Annotations can explain terminology, provide historical context, elaborate on an argument, identify relevant ideological framing, fact-check factual claims where appropriate, or connect the passage to other texts and ideas.

**User Interaction:**  
The user opens a text and selects or views annotated passages. Annotations appear alongside the original material and can be expanded or hidden.

**Input:**  
The selected passage, surrounding text, document metadata, relevant external sources, and reader context.

**Output:**  
Contextual annotations attached to specific portions of the text.

**AI Involvement:** Hybrid.

**Expected Workflow:**  
The system supplies the selected passage and necessary context to the annotation component. Depending on the annotation type, the agent may retrieve additional information before generating an annotation. The annotation remains visually distinct from the original text.

**Error/Alternative Cases:**  
If an annotation requires information that cannot be verified, the system indicates uncertainty. AI-generated commentary must remain distinguishable from the author’s original words.

---

### **F07 — Intelligent Reading Recommendations**

**Description:**  
The agent recommends actual texts for users to read based on a topic, research question, current event, previous reading, or the user’s interests and knowledge.

**User Interaction:**  
The user can explicitly ask what to read, select recommended readings attached to another feature, or browse personalized recommendations.

**Input:**  
Topic or question, available texts, reader model, reading history, interests, and research context.

**Output:**  
A ranked set of recommended readings with explanations of why each text is relevant.

**AI Involvement:** Hybrid.

**Expected Workflow:**  
The agent determines the user’s learning objective, considers the user’s existing knowledge and reading history, searches available material, and recommends appropriate texts. Recommendations link directly to texts when they are available within the library.

**Error/Alternative Cases:**  
If the system has little information about the reader, recommendations can initially be based on the requested topic rather than personalization. The system should not imply that a recommendation is personalized when insufficient user information exists.

---

### **F08 — Prerequisite-Guided Learning**

**Description:**  
The system identifies concepts, events, theories, or texts that a user should understand before approaching more advanced material. It can create a learning path that encourages the user to build the required background rather than simply giving them an immediate simplified answer.

**User Interaction:**  
When opening a text, researching a topic, or asking a question, the user may receive prerequisite suggestions. The user can open the suggested material or indicate that they already understand it.

**Input:**  
The target topic or text, its prerequisite concepts, and the user’s current reader model.

**Output:**  
An ordered set of prerequisite concepts and recommended readings or learning steps.

**AI Involvement:** Hybrid.

**Expected Workflow:**  
The agent identifies knowledge assumed by the requested material, compares those prerequisites with the user’s known reading history and knowledge profile, and recommends only the relevant gaps. Completing material can update the reader model.

**Error/Alternative Cases:**  
The agent may incorrectly estimate the user’s knowledge. The user can indicate that a prerequisite is already understood, skip recommendations, or correct the system’s assessment.

---

### **F09 — Historical Context Exploration**

**Description:**  
The system helps users understand the historical background behind contemporary or historical political issues. Rather than reducing that background to a short AI summary, it organizes relevant events, explanations, sources, and readings into an explorable context.

**User Interaction:**  
The user can request historical context directly or open contextual links associated with a news event, source, annotation, or research result.

**Input:**  
An event, topic, period, question, and relevant reader context.

**Output:**  
A structured historical explanation containing significant preceding events, relationships, source material, and suggested readings.

**AI Involvement:** Hybrid.

**Expected Workflow:**  
The agent identifies the historical developments relevant to understanding the topic, retrieves supporting material, organizes important events and relationships, and recommends deeper readings where appropriate.

**Error/Alternative Cases:**  
When the historical interpretation of an issue is disputed, the system should distinguish established facts from interpretations and expose meaningful disagreements where relevant.

---

### **F10 — Source and Framing Comparison**

**Description:**  
The system compares how different sources discuss the same event or issue. It can highlight differences in terminology, emphasis, framing, assumptions, included or omitted context, and the evidence or authorities relied upon by each source.

**User Interaction:**  
The user selects multiple sources manually or requests a comparison from an event or research view.

**Input:**  
Two or more sources concerning the same or closely related subject.

**Output:**  
A structured comparison showing similarities, differences, relevant passages, and AI-generated observations about framing.

**AI Involvement:** Hybrid.

**Expected Workflow:**  
The system retrieves the selected texts, identifies comparable claims and passages, and uses the LLM to analyze meaningful differences. The results are presented alongside links or excerpts so the user can inspect the underlying material.

**Error/Alternative Cases:**  
If sources address substantially different aspects of an event, the system should warn that direct comparison may be misleading. Interpretive judgments about bias or framing should be identified as analysis rather than presented as objective fact.

---

### **F11 — Marxist Theoretical Analysis**

**Description:**  
The agent helps the user examine political and historical issues using Marxist theoretical concepts. Depending on the issue, this may involve concepts related to class, labour, capital, ownership, the state, imperialism, ideology, material conditions, or other relevant areas of Marxist theory.

**User Interaction:**  
The user requests a Marxist analysis of an event or topic, or accesses theoretical connections suggested within research and reading views.

**Input:**  
The issue being examined, relevant factual/source material, Marxist theoretical material, and optionally a particular theoretical framework requested by the user.

**Output:**  
A structured Marxist analysis accompanied by relevant theoretical sources and suggested readings.

**AI Involvement:** AI-based/Hybrid.

**Expected Workflow:**  
The agent determines which Marxist concepts are relevant, retrieves appropriate theoretical material, relates that theory to the evidence already collected, and presents possible interpretations while linking the user to the underlying texts.

**Error/Alternative Cases:**  
The agent should avoid presenting an interpretation as an uncontested fact. Where the application of a theory is disputed or uncertain, this should be communicated to the user.

---

### **F12 — Comparison of Leftist Perspectives**

**Description:**  
Although the platform is primarily oriented toward Marxism-Leninism, it does not assume that there is a single leftist interpretation of every political question. The system can present meaningful disagreements between Marxist and other leftist traditions and allow users to examine the arguments and sources for themselves.

**User Interaction:**  
The user requests alternative perspectives or selects a perspective-comparison option while viewing an event, research result, or theoretical question.

**Input:**  
The political or theoretical issue, relevant source material, and applicable leftist perspectives.

**Output:**  
A structured comparison of relevant positions with representative arguments, source material, and recommended readings.

**AI Involvement:** Hybrid.

**Expected Workflow:**  
The agent identifies leftist traditions with materially different positions on the issue, retrieves representative material, summarizes the nature of the disagreement, and presents supporting passages and readings for each perspective.

**Error/Alternative Cases:**  
Not every issue has meaningful positions from every political tradition. The system should include only perspectives for which relevant material can be found and should avoid inventing artificial disagreements merely to produce balance.

---

### **F13 — Adaptive Reader Model**

**Description:**  
The system maintains an evolving model of the individual reader so that the agent can adapt as the user learns. The model can include reading history, areas of demonstrated knowledge, possible knowledge gaps, interests, preferred topics, learning progress, and political perspectives or interests that the user voluntarily provides or reveals through their interactions.

**User Interaction:**  
The reader model develops through normal use of the application and through information explicitly supplied by the user. The user can inspect and correct the system’s understanding of them through a profile or learning-model interface.

**Input:**  
Reading activity, completed material, research activity, user feedback, saved interests, interactions with the agent, and information explicitly supplied by the user.

**Output:**  
A structured and continuously updated representation of the user’s knowledge, interests, reading history, and learning needs.

**AI Involvement:** Hybrid.

**Expected Workflow:**  
Relevant interactions produce observations about the reader. The system updates the reader model and makes that information available to features such as recommendations, prerequisite detection, and conversational responses. The model changes as the user’s knowledge and interests develop.

**Error/Alternative Cases:**  
The system may infer something incorrectly. Users can inspect, correct, or remove inaccurate assessments. Sensitive or uncertain inferences should not be treated as established facts about the user.

---

### **F14 — Personalized and Adaptive Assistance**

**Description:**  
The agent uses the Reader Model to adapt the experience to the individual user. Explanations can account for what the reader already knows, recommendations can address knowledge gaps, and research results can connect to the user’s interests without requiring the user to repeatedly explain their background.

**User Interaction:**  
Personalization occurs throughout normal use. The user can also request more or less detail, indicate familiarity with a subject, or override recommendations.

**Input:**  
Current user request, research context, Reader Model, reading history, interests, and user preferences.

**Output:**  
Personalized explanations, reading recommendations, prerequisite suggestions, research directions, and other assistance.

**AI Involvement:** Hybrid.

**Expected Workflow:**  
When another feature requests personalized assistance, the system retrieves relevant information from the Reader Model and supplies it as context to the agent. The agent adapts the depth, terminology, assumed prior knowledge, examples, and recommended material accordingly.

**Error/Alternative Cases:**  
If little is known about the user, the agent provides a general response rather than making unsupported assumptions. Users can disable or override personalization and correct inaccurate information in their Reader Model.

---

### **F15 — Personal Research and Reading Workspace**

**Description:**  
The workspace allows users to preserve and organize their studies over time. Users can save texts, passages, news events, research results, annotations, reading progress, and other material so that investigations do not disappear when an interaction ends.

**User Interaction:**  
The user can save material from the reader, news dashboard, event view, research interface, or conversational interface. Saved material can later be browsed and reopened from a personal workspace.

**Input:**  
Texts, passages, research results, events, annotations, reading progress, and organizational information supplied by the user.

**Output:**  
A persistent organized collection of the user’s research and reading activity.

**AI Involvement:** Primarily deterministic, with optional AI assistance for organization and retrieval.

**Expected Workflow:**  
When the user saves an item, the system stores the item and its relevant metadata. The user can later search, organize, reopen, or continue working from saved material. Previous research context can be restored when appropriate.

**Error/Alternative Cases:**  
If an external source is no longer available, the system retains whatever metadata or legally stored content is available and informs the user that the original source cannot currently be accessed.
